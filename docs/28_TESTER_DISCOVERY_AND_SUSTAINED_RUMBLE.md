# 手柄发现列表和持续振动修复

## 手柄测试

- 上方手柄源只列出已建立连接的 NS2 BLE 设备和 SDL 当前枚举的所有设备，包括本应用创建的模拟手柄。
- 未连接时不再放置 NS2 占位卡；设备断开后随现有设备刷新移除。
- 本应用的模拟设备使用已有会话归属 / 序列号判定，不以 VID/PID 单独判断，以免把同型号实体设备误标为模拟设备。其他 Windows 设备标为系统手柄，明确提示其实体 / 模拟来源未确认。
- 下方模拟手柄是默认折叠的映射参考区，始终使用上次保存的映射；不因模拟设备枚举成功而切换为实际接收，也不会启动模拟器。

## 振动

问题：Xbox / NS1 反馈转换后只发送一次有限时长的 NS2 BLE 振动包。原来的 500 ms 看门狗也会把未变化的持续马达强度当作过期数据。宿主的持续时间由启动和停止指令表达，并不要求连续发送相同的强度。

修复：普通马达强度以及 NS1 强度转码显式标记为持续状态，BLE 单写入循环每 12 ms 补发当前强度并更新包序号，直到收到新强度或零强度。HD / 音频帧保持流式行为，不重复播放旧波形；失去流数据时保留 500 ms 停止保护。播放状态仅属于当前 BLE 连接，断开后不会带到下一次连接。停止模拟器时在终止反馈生产者后再次清零，并拒绝关闭期间的迟到反馈。

参考区的停止测试按钮同时修正为停止当前 Windows 输入源，而不是无关的测试设备。

## 验证

自动检查覆盖 Xbox / NS1 单次启动后 5 秒持续输出、明确停止、强度替换、HD 流不重复播放、流超时停止、连接间状态隔离以及会话关闭后的迟到反馈。

离线渲染使用实际页面和列表同步方法，检查实体 / 模拟设备并列、断开清空、参考区默认折叠，以及两种宽度下折叠 / 展开 / 空列表的布局。未连接实体硬件或改变用户配置；实际振感和蓝牙写入节奏仍需手柄复测。
