# NS2 Pro：当前 BLE 协议实现

[协议目录](README.md) · [内部虚拟 NS2 格式](VIIPER.md) · [核对结果](COVERAGE.md)

适用版本：**1.0.1**；核对日期：2026-09-27。本文记录本应用实际使用的字节与条件，不将逆向观察当作 Nintendo 官方规范。实体 NS2 USB 输入由 SDL 处理；USB 手动主机注册、状态读取和删除见 [USB 注册说明](../29_NS2_USB_REGISTRATION.md)。下文是应用直接管理的 BLE 路径。

## 广播与 GATT

[Ns2Advertisement](../../ControllerForwardingTool/Bluetooth/Ns2Advertisement.cs) 接收去掉公司 ID `0x0553` 后的厂商负载：至少 16 字节，`0..2 = 01 00 03`，`3..4 = 7E 05`，`5..6 = 69 20`，`10..15` 为小端目标主机地址。目标为零表示配对广播。其余字段不在当前解析器中解释。

名称、厂商字段及已记住的地址用于候选筛选，不代表身份认证。普通自动连接需 2 秒内广播；注册/重新配对判断使用 5 秒内的配对广播。目标主机或 `IsConnectable` 不作为通用拒绝条件，避免不完整广播误拦截 SYNC。见 [BleAutoConnectPolicy](../../ControllerForwardingTool/Bluetooth/BleAutoConnectPolicy.cs) 与 [BleDeviceHistory](../../ControllerForwardingTool/Bluetooth/BleDeviceHistory.cs)。

[Ns2BleTransport](../../ControllerForwardingTool/Bluetooth/Ns2BleTransport.cs) 动态发现特征，不固定属性 handle：

| 特征 | UUID | 当前用途 |
| --- | --- | --- |
| FD2 | `ab7de9be-89fe-49ad-828f-118f09df7fd2` | 主输入通知，必须取得有效首帧 |
| ACK | `c765a961-d9d8-4d36-a20a-5315b111836a` | 初始化回复及独立注册事务回复 |
| Command | `649d4ac9-8eb7-4e6c-af44-1ea54fe5f005` | 初始化/注册命令写入 |
| Rumble | `cc483f51-9258-427d-a939-630c31f72b05` | 33 字节 BLE 震动写入 |
| ProInput | `7492866c-ec3e-4619-8258-32755ffcc0f8` | 可选低频读取 `0x09` 对应负载的电量档位 |
| Battery Level | `00002a19-0000-1000-8000-00805f9b34fb` | 可用时读取标准百分比 |

## 初始化与连接参数

当前 [Ns2InitProfile](../../ControllerForwardingTool/Bluetooth/Ns2InitProfile.cs) 版本为 `bridge-v6.2.32-r3-no-unnegotiated-pairing`，**14 条**，没有无协商的 `0x15/03` 注册提交。顺序和完整字节如下，不能把每条未知命令的用途自行命名为官方语义：

| 5 | `1191010300000000` |
| 6 | `0A9101080014000001FFFFFFFFFFFFFFFF3500460000000000000000` |
| 7 | `0C91010400040000FF000000` |
| 8 | `0391010A0004000009000000` |
| 9 | `1091010100000000` |
| 10 | `0191010C00000000` |
| 11 | `019101010004000000000000` |
| 12 | `09910107000800000100000000000000` |
| 13 | `0291010400080000097E0000A8300100` |
| 14 | `0291010400080000097E0000E8300100` |

命令写失败最多尝试 3 次；普通初始化 ACK 等待 1500 ms，超时记录后继续，**内容尚未严格校验**。随后订阅 FD2，等待有效首帧最多 6 秒；连接总限时 60 秒。注册事务有独立的严格回复校验，不能将两种 ACK 处理混写。

代码请求 Windows `ThroughputOptimized` 并持有请求到断开，记录 `ConnectionInterval × 1.25 ms` 和从机延迟。历史参考工程的“向描述符写 133”不是当前应用行为；这里也没有完整实现该参考工程的工厂 IMU 校准块读取与应用。当前参数请求不保证特定 Hz。

## FD2 解码

偏移从 GATT 通知负载首字节开始，**不包含 HID Report ID 或 ATT 头**。[Fd2Decoder](../../ControllerForwardingTool/Protocol/Ns2/Fd2Decoder.cs) 要求长度至少 60；按钮原始值与 `0xFC300020` 按位与非零则拒绝。其他未解码字段不做完整结构校验，也不限制负载必须恰为 60 字节。

| 偏移 | 类型 | 当前解释 |
| --- | --- | --- |
| 4–7 | u32 | 原始按钮掩码 |
| 10–12 / 13–15 | 各 3 字节 | 左/右摇杆，每轴 12 位 |
| 31–32 (`0x1F`) | u16 | 电池毫伏值，另由 `Ns2Battery` 验证 2500–5000 范围 |
| 42–45 | u32 | 运动时间戳，按微秒传递 |
| 48/50/52 | i16 × 3 | Accel X/Y/Z |
| 54/56/58 | i16 × 3 | Gyro X/Y/Z |

轴解包：`X = b0 | ((b1 & 0x0F) << 8)`，`Y = (b1 >> 4) | (b2 << 4)`。内部轴范围 0–4095，中位 2048，Y 向上。体感换算使用项目的 `4096 counts/g` 与 `16.384 counts/(°/s)` 约定，并可进行会话静置零偏校准；不等于已经验证所有固件的工厂标定。

| 原始掩码 | 按键 | 原始掩码 | 按键 |
| --- | --- | --- | --- |
| `00000001` / `00000002` | Y / X | `00000004` / `00000008` | B / A |
| `00000040` / `00000080` | R / ZR | `00000100` / `00000200` | Minus / Plus |
| `00000400` / `00000800` | R3 / L3 | `00001000` / `00002000` | Home / Capture |
| `00004000` | C | `00010000` / `00020000` | Down / Up |
| `00040000` / `00080000` | Right / Left | `00400000` / `00800000` | L / ZL |
| `01000000` / `02000000` | GR / GL | | |

[Ns2Battery](../../ControllerForwardingTool/Protocol/Ns2/Ns2Battery.cs) 对 `0x09` 对应 BLE 负载要求至少 15 字节：`payload[1]` 的 bit0 为外接电源，bit1 为充电，bit2–5 为 0–9 档；bit6–7 非零或档位超过 9 则拒绝。界面优先用标准 Battery Level 百分比，否则显示档位，再附加有效电压；不会把电压线性转换成精确百分比。

## 独立主机注册

[Ns2PairingProtocol](../../ControllerForwardingTool/Bluetooth/Ns2PairingProtocol.cs) 只在显式开启 `RegisterHostOnSync` 且有新鲜 SYNC 广播的连接中运行；默认关闭，在有效 FD2 后执行。

命令头为 `15 91 01 <sub> 00 <payload长度> 00 00`，负载从 8 开始。回复必须匹配 `response[0]=15`、`[1]=01`、`[2]=01`、`[3]=sub`、`[5]=78`、`[8]=01` 及最短长度。

| 顺序/子命令 | 发送负载 | 回复负载最短长度及校验 |
| --- | --- | --- |
| 1 / `01` | 14 字节：`00 02` + 本机地址小端 6 字节重复两遍 | 9；负载 `[2]=01`、`[3..8]` 为当前手柄地址 |
| 2 / `04` | `00` + 随机主机材料 16 字节 | 17；取负载 `[1..16]` 为设备材料 |
| 3 / `02` | `00` + 随机挑战 16 字节 | 17；比较 16 字节 AES 确认值 |
| 4 / `03` | `00` | 1；验证最终提交确认，不自动重发 |

AES-128 ECB 无填充：两份材料按位异或后反转字节序作为 key，挑战反转后作为 block，加密结果不再反转；固定时间比较回复。单次写入与等待合计限时 3 秒；失败中止，不跳过验证。最终确认后仅保存主机地址/时间，材料在事务退出时清零。该证据不是 Windows SMP bond；提交 ACK 丢失不能证明手柄没有保存。

## 震动与未实现范围

[Pro2BleRumblePacketEncoder](../../ControllerForwardingTool/VirtualDevice/Source/Pro2BleRumblePacketEncoder.cs) 接收 64 字节 raw02 中间报告，要求 ID `02` 且 `report[1]` 高半字节为 `50`。读取左右第一个 5 字节震动帧（偏移 2、18），转换为 33 字节 BLE 包：`[0]=00`，左右 16 字节块位于 1、17；每块首字节 `50 | (packetId & 0F)`，接一个有效 5 字节帧和两个零幅度帧。

5 字节 BLE 帧按小端 40 位打包：低频 9 bit、低频 tone 1 bit、低频幅度 10 bit、高频 9 bit、高频 tone 1 bit、高频幅度 10 bit。当前 tone 为 false，幅度按 `raw × 1023 × gain / 29000` 限幅。它不是把 USB 报文完整原样转发，也不重放每块全部三个原始波形槽。

单写循环约 12 ms；普通强度持续补发直至停止/替换，HD 流不重复旧帧，500 ms 无流数据停止。玩家灯字段虽在中间对象中保留，当前 BLE 写回没有实现 LED 控制。NFC、完整工厂校准、所有未知 FD2 字段、固件升级和完整主机兼容均不在当前实现范围。

1.0.1 的设备卡识别振动为 25% 强度、250 ms 限时脉冲，`BleRumblePlayback` 到期发送停止；再次点击重置时长，游戏反馈替换后清除脉冲计时。该时限不用于普通持续游戏震动。
