# PS5 DualSense / DualSense Edge 通信协议

> 历史研究归档：本文硬件报文表来自当时的 Linux/SDL 资料，并非本项目直接实现的 HID 解析器。当前输入、虚拟输出与反馈处理见 [PS5 / Edge 当前协议](../PS5.md)，当前 NS1 已支持体感转换。

核查日期：2026-09-26。本资料分析公开开源驱动中的 USB / 蓝牙 HID 报文，不是 Sony 官方完整协议。普通 DualSense 常见 VID:PID 为 `054C:0CE6`，Edge 为 `054C:0DF2`；第三方兼容设备与固件可能有不同报文，不可仅凭名称套用。

## 来源与复核点

- Linux [hid-playstation.c](https://github.com/torvalds/linux/blob/master/drivers/hid/hid-playstation.c)：报告结构、长度、CRC、工厂校准、传感器时间、电量、触摸和兼容震动。
- SDL **release-3.4.16** [SDL_hidapi_ps5.c](https://github.com/libsdl-org/SDL/blob/release-3.4.16/src/joystick/hidapi/SDL_hidapi_ps5.c)：普通/增强蓝牙模式、Feature 读取、传感器单位转换、Edge 与兼容设备分支。
- 项目本地对应代码：`tools/sdl-build/SDL3-3.4.16/src/joystick/hidapi/SDL_hidapi_ps5.c`。

核查的 Linux 文件 SHA-256：`48A08DDDF8D276A611195311A29CD4F113A949A1F5431ECC84B0396B106EC896`。Linux 链接为可变分支，应按目标版本再核对结构大小。

## 1. 传输模式与长度

以下长度均含 Report ID。USB 输出长度按 Linux 驱动的结构定义列出；HID API 的缓冲区长度和填充要求还应服从实际设备报告描述符，不能把缓冲区大小直接当有效报文长度。

| 方向 / 通道 | Report ID | Linux 结构长度 | 说明 |
| --- | --- | --- | --- |
| USB 输入 | `01` | 64 | 完整输入状态 |
| 蓝牙增强输入 | `31` | 78 | 附加头与末尾 CRC |
| USB 输出 | `02` | 63 | 包含有效字段标志、震动和灯光等控制 |
| 蓝牙增强输出 | `31` | 78 | 序号/标签、输出状态、CRC |
| Feature 校准 | `05` | 41 | IMU 工厂标定参数 |
| Feature 配对信息 | `09` | 20 | 地址等设备信息 |
| Feature 固件信息 | `20` | 64 | 固件 / 硬件信息 |

蓝牙初始模式也可能收到 `01` 的简化输入，不能按 USB `01` 的完整传感器布局解析。SDL 区分简单和增强模式；是否成功启用增强报告关系到陀螺仪、触摸、电量等能力。

## 2. 完整输入公共部分

Linux `dualsense_input_report` 的公共部分为 63 字节。**公共偏移不含 USB/蓝牙头**：USB 公共起点是全包 `data[1]`，蓝牙增强模式是 `data[2]`。先验证 Report ID、长度以及蓝牙 CRC，再读取下表。

| 公共偏移 | 大小 | 内容 |
| --- | --- | --- |
| 0 / 1 / 2 / 3 | 各 1 | LX / LY / RX / RY，0…255，中心约 128，Y 向下增大 |
| 4 / 5 | 各 1 | L2 / R2 模拟行程，0…255 |
| 6 | 1 | 输入序号 |
| 7…10 | 4 | 按键位；第一个字节低 4 bit 是 Hat |
| 11…14 | 4 | 保留字段 |
| 15…20 | 6 | 三轴陀螺仪，有符号小端 16 bit × 3 |
| 21…26 | 6 | 三轴加速度，有符号小端 16 bit × 3 |
| 27…30 | 4 | 传感器时间戳，小端 32 bit |
| 31 | 1 | 保留 |
| 32…39 | 8 | 两个触摸点，各 4 字节 |
| 40…51 | 12 | 保留/设备扩展区，不作跨型号假定 |
| 52…54 | 3 | 电池、充电/连接状态 |
| 55…62 | 8 | 保留 |

例如 USB 的陀螺仪绝对偏移是 **16**，蓝牙增强输入是 **17**；绝不能共用固定全包偏移。公共按钮字节 0 的 bit4…7 是 □、×、○、△。字节 1 的 bit0…7 为 L1、R1、L2 开关、R2 开关、Create、Options、L3、R3。Hat 的 0…7 顺时针表示上、右上、右、右下、下、左下、左、左上，8 为居中。PS、触摸板按下及其他扩展位应继续按驱动的设备分支解析。

触摸点包含联系 ID / 非活动标记，以及打包的 12 bit X 和 12 bit Y。Linux 的 DualSense 触摸区域常量为 1920 × 1080；两点的“有效”标记不能与坐标是否为零混为一谈。模拟扳机行程与 L2/R2 开关位也是两个概念。

## 3. 传感器校准与时间

原始传感器的整数不是直接的 °/s 或 g。Linux / SDL 先读 `05` 工厂校准，再根据每轴偏置、正负端点和速度参考计算灵敏度。Linux 输出归一化目标为每 °/s 1024 单位、每 g 8192 单位；这**不表示任意设备原始 gyro 除以 1024 就是 °/s**。

SDL 对外提供陀螺仪 rad/s 与加速度 m/s²，本项目使用：

```text
角速度 °/s = SDL gyro × 180 / π
加速度 g   = SDL accel / 9.80665
```

传感器时间戳的硬件单位约为 1/3 μs。Linux 按差分处理 32 bit 回绕，再除以 3 换算 μs。不要把 UI 刷新时间当成每个 IMU 样本的时间，也不要用同一个重复样本累计校准进度。

工厂灵敏度校准与静置零偏校准分属不同层：前者把原始值换成物理量，后者扣除当前温度/状态下的静态漂移。本项目的手动/自动校准在 SDL 单位转换后执行，缺失或超时的传感器不参与采样。

## 4. 蓝牙 CRC

Linux `ps_check_crc32` / 输出发送路径对蓝牙包使用 CRC32：输入前缀 `A1`，输出前缀 `A2`，需要校验的 Feature 响应前缀 `A3`。末尾 4 字节是小端 CRC；“前缀”参与运算但不是又在 HID 报文前发送一个字节。

等价算法描述：

```text
crc = crc32_le(0xFFFFFFFF, [prefix])
crc = ~crc32_le(crc, report[0 .. length-4])
report[length-4 .. length] = little_endian_u32(crc)
```

不同库的 CRC 初值和最终异或可能已内置，移植时需对照抓包验证，避免重复取反。USB 报文不应强行套用蓝牙末尾 CRC 格式。

## 5. 主机输出、震动与高级能力

公共输出块在 Linux 中长 47 字节。USB 在 1 字节 Report ID 后放该块；蓝牙在 Report ID、seq_tag、tag 三字节后放该块，并以保留区和 CRC 补足 78 字节。蓝牙 tag 为 `10`，序号位需要按驱动推进。

| 公共输出偏移 | 内容 |
| --- | --- |
| 0 / 1 | valid_flag0 / valid_flag1，指示此次哪些控制字段生效 |
| 2 / 3 | 兼容震动的右/左马达力度 |
| 4…9 | 耳机、扬声器、麦克风及静音等控制字段 |
| 10…36 | Linux 结构保留区；不能推断为任意设备均可清零覆盖 |
| 37 / 38 | audio_control2 / valid_flag2 |
| 39…40 | 保留 |
| 41…46 | 灯光设置、亮度、玩家 LED、RGB |

**有效字段标志不可省略**：只改马达或 RGB 数值而没有相应标志，设备可能忽略该字段；盲目把整块置为有效可能影响音频与灯光。普通兼容双马达震动、音频触觉、自适应扳机是不同能力，不能通过同一对强度数值无损互换。

Edge 与兼容设备有背键、功能键或报告差异，应参考 SDL 的对应分支；本文没有宣称覆盖所有 Edge 扩展、固件命令、认证与触觉音频协议。

## 6. 本项目接入边界

实体 PS5 / Edge 输入通过 SDL 读取标准按键、摇杆、模拟扳机，以及 SDL 成功启用的陀螺仪/加速度。跨型号输出保持面键物理位置，使用选中设备的校准体感；目标缺少功能则不输出。

虚拟 PS5 输出使用 `VirtualReportEncoder` → VIIPER 的 **33 字节内部消息**，不是上述 64 字节 USB HID 输入。消息包含有符号 8 bit 摇杆、按键掩码和内部体感字段；VIIPER 负责转换到虚拟 USB 设备协议。不要把内部消息偏移写进 DualSense HID 文档或直接发给真实手柄。

Windows 输入侧反馈只使用 SDL 普通震动接口。触摸坐标、麦克风、扬声器、音频触觉和自适应扳机不会由本版通用转换补齐。没有 IMU 的 Xbox 转 PS5 时传感器字段为零；当前有有效 IMU 的 PS5 转 NS1 可经过坐标与单位转换输出，且需要 NS1 主机启用 IMU。虚拟 PS5 后端接收的触觉音频反馈是另一条路径，见 [PS5 当前协议](../PS5.md)。
