# 手柄转发工具 / Controller Forwarding Tool UI 设计规范

> 项目：`D:\github\NS2ProWin11\ControllerForwardingTool`，.NET 10 / Avalonia 12，目标系统为 Windows 11。  
> 参考：`D:\github\UI-Design-Rules.md`（Virtual Driver Control UI 设计规则 v1.1）。沿用其桌面工具视觉语言、信息层级和状态反馈方式；设备、页面与文案按 NS2 Pro 蓝牙输入和 NS1 Pro 虚拟输出重新设计。  
> 版本：1.1，2026-09-26。本文保留设计目标。当前已实现概览、蓝牙、手柄测试、映射说明、虚拟手柄、日志、设置和关于页面；Steam 检测和映射编辑尚未实现；配置保存已在 r3 实现。实现状态见 [06](06_PROTOTYPE_STATUS.md)。

## 本次测试页与虚拟设备页

测试页参考用户提供的网页手柄测试截图，采用浅色卡片、曲线手柄外形、橙色按键高亮、双摇杆坐标图和原始按钮/轴读数。原生 Avalonia 控件绘制，不依赖网络或网页嵌入。输入源可在 Windows 手柄、实体 NS2 BLE 和 NS1 输出映射预览间切换；Windows 手柄自动发现和热插拔。未知 HID 仅显示原始编号，不能假设图形按键语义。

r3 以 All Controller Test 的设备/线框/摇杆双栏结构为浅色参考，增加死区和行程覆盖图。虚拟页包含 PS5 / NS2 / Xbox / Edge / NS1 图片卡片模式选择、自动挂载/停止、驱动状态与安装/修复/卸载入口。挂载、有效 BLE 输入、Windows 测试和游戏验证分别呈现。用户可先启动虚拟设备，再唤醒 NS2。

## 1. 产品目标与信息原则

用户进入应用后，应在首屏回答四个问题：

1. 电脑蓝牙适配器是否可用，真实 NS2 Pro 是否发现并收到有效输入？
2. 虚拟 NS1 Pro 所需的输出方案是否已配置，驱动或设备服务是否在运行？
3. 当前输入能否经过映射送到虚拟设备，哪些功能已验证？
4. 失败发生在哪一步，下一步应做什么？

首版核心任务是**让真实 NS2 Pro 经蓝牙接入，并将输入送至 Windows 可枚举的虚拟 NS1 Pro**。Eden 是实体 NS1 Pro 的输入端研究资料，不等于本项目已有虚拟设备输出能力。Steam 是否识别、游戏是否接收、震动是否工作，都必须以各自检查或用户实测显示，不随“蓝牙已连接”自动变为成功。

UI 以连接链路为主线，不在主界面暴露 GATT UUID、报文十六进制、USB 描述符和驱动内部调用。原始值放在“诊断详情”，并提供复制与脱敏导出。所有状态除颜色和图标外均有文字。

## 2. 导航、窗口与首屏

| 区域 | 规范 |
| --- | --- |
| 主窗口 | 默认 `1400 × 860`，最小 `1050 × 680`；初版浅色主题，窗口背景 `Canvas` |
| 侧栏 | 白底，展开宽 `210`、折叠宽 `68`；导航项高 `52`、图标 `20 × 20`、文字 `14` SemiBold、圆角 `8`；折叠后保留 Tooltip |
| 顶栏 | 高 `64`，白底、底边 `ShellBorder`；左侧页名，右侧显示全局连接摘要与“打开日志”入口 |
| 内容区 | 外边距 `20`；页面内部滚动，顶栏和侧栏固定；最小宽度不依赖水平滚动完成主任务 |
| 导航顺序 | **概览 → 蓝牙连接 → 按键映射 → 虚拟手柄 → 日志 → 设置**；“关于”固定在侧栏底部 |

“概览”首屏从左到右或从上到下展示一条**四段状态链**：蓝牙适配器 → 实体 NS2 Pro → 虚拟 NS1 Pro → 游戏验证。每段包含状态词、一句解释和一个可执行入口。链路上方保留唯一主操作：按当前阶段显示“扫描手柄”“连接手柄”或“启动虚拟手柄”；不同时摆放多个同权重的蓝色按钮。

导航始终可进入，不因驱动未安装而消失。页面不可操作时展示原因和前置动作；不能用空白、无限旋转动画或单独的禁用按钮表达。顶栏不得将“蓝牙连接成功”简写为“手柄可用”。

## 3. 设计令牌

继承参考文档的浅色系统，作为 `App.axaml` 资源集中管理；页面 XAML 不散落硬编码颜色。数字为 Avalonia 设计单位，在 Windows 缩放下验证实际可读性。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `Canvas` | `#F4F7FB` | 页面背景 |
| `Surface` | `#FFFFFF` | 侧栏、顶栏、卡片 |
| `Border` | `#DFE6EF` | 卡片和控件边框 |
| `ShellBorder` | `#E4E9F0` | 应用壳层分隔 |
| `TextPrimary` | `#172033` | 标题、关键状态 |
| `TextSecondary` | `#667085` | 正文中的次级说明 |
| `TextTertiary` | `#98A1AF` | 辅助标签；不可单独承载关键信息 |
| `Accent` | `#1677FF` | 图形强调、焦点、非小字高亮 |
| `AccentStrong` | `#0958D9` | 白字主按钮及白底文字链接；满足普通文字对比度要求 |
| `AccentSoft` | `#E8F1FF` | 导航选中、信息提示背景 |
| `SuccessText` / `SuccessSurface` | `#18794E` / `#EAF7EF` | 已验证运行状态 |
| `WarningText` / `WarningSurface` | `#9A6700` / `#FFF7E6` | 待验证、需操作、延迟升高 |
| `DangerText` / `DangerSurface` / `DangerBorder` | `#BE123C` / `#FFF1F2` / `#FECDD3` | 失败、卸载或清除操作 |

参考稿的 `#1677FF` 保留为系列蓝色，但**小号白字填充按钮**使用更深的 `AccentStrong`：`#1677FF` 与白色的对比度约为 `4.10:1`，不足普通正文的 `4.5:1` 目标。页面标题 `24` Bold，卡片标题 `16` SemiBold，关键状态 `18–22` SemiBold，正文和表单 `14`，辅助说明 `12`。默认字体沿用项目现有 Inter，中文由系统字体回退，检查混排宽度。

基础卡片白底、`1` 单位边框、圆角 `10`、内边距 `16`；页面区块纵向间距 `14`，并排卡片间距 `12`，卡片内控件间距 `8–12`。按钮最小高度 `34`、圆角 `6`、水平内边距至少 `13`。危险操作采用浅红样式，且必须有动词和对象，例如“停止虚拟手柄”“卸载 USB/IP 驱动”。

## 4. 页面内容与主操作

| 页面 | 首屏要回答的问题 | 主要操作 | 下方内容 |
| --- | --- | --- | --- |
| **概览** | 链路在哪一段中断；真实输入和虚拟输出分别是否运行 | 按当前阶段展示“扫描”“连接”或“启动输出” | 当前手柄、实际输入更新、虚拟设备状态、最近一次错误；每段可跳往详情 |
| **蓝牙连接** | 蓝牙是否可用、扫描发现什么、哪只设备正在连接、何时收到有效报文 | 扫描／停止扫描、连接／断开、重试 | 候选设备列表、信号强度、上次连接、连接阶段、实时按键和摇杆预览、IMU 数据是否到达 |
| **按键映射** | NS2 的输入怎样映射到 NS1、额外键如何处理 | 保存映射、恢复默认 | A/B/X/Y、方向、肩键、摇杆、Home/Capture、C/GL/GR 策略；实时来源→目标预览、死区和轴反向设置 |
| **虚拟手柄** | 本地依赖包、驱动安装、设备挂载、输入提交各处于什么状态 | 检查环境、显式安装／启动／停止 | 选择中的输出方案、签名和版本、Windows 枚举结果、Steam／游戏验证提示、震动和灯光测试（功能就绪后） |
| **日志** | 哪一步失败、怎样复现 | 筛选、复制、导出脱敏诊断 | 时间、级别、模块、操作 ID、摘要；展开查看错误码和有限原始报文 |
| **设置** | 应用如何重连、记录日志和管理配置 | 保存设置 | 自动重连、启动行为、主题、诊断级别、配置备份；明确默认值与修改影响 |

首版不把“NS1 Pro 官方协议”“Steam 已识别”“全功能震动”当成产品承诺。未实现能力展示为“尚未提供”，并附已知范围；不要显示看似可用但点按无效的按钮。虚拟设备页应把“本地存在 USB/IP 安装器”“已安装驱动”“已挂载虚拟设备”分成不同字段。随项目复制的第三方安装器仅是可选原型依赖，不应在首次启动时自动执行。

### 蓝牙连接页的候选卡片

显示名称、信号强度、最近发现时间和“连接”按钮；名称可能伪造，卡片不标“已确认为 NS2 Pro”。只有 GATT 特征检查、初始化和实时 FD2 报告成功后，状态才为“输入正常”。蓝牙地址默认脱敏，完整值仅在诊断详情中由用户主动复制。多设备同名时用脱敏地址尾段和最近时间区分。

### 映射页的操作规则

“保存映射”表示配置持久化并读回；“应用到运行中的虚拟设备”表示收到下一帧并确认输出路径仍在运行，两者反馈分开。C、GL、GR 默认标记为“未映射”，提供“忽略 / 替代按钮 / 组合键”选择，且展示冲突提示。录入按键时只捕获当前已连接真实手柄，超时或断线可取消；有两个来源映到一个目标时要显示结果。

## 5. 状态模型与显示文案

UI 状态应从蓝牙服务、协议解析器、输出服务的实际结果派生，不用单个 `IsConnected` 布尔值覆盖全部。最低状态集合：

| 分段 | 必须区分的状态 | 文案要点 |
| --- | --- | --- |
| 蓝牙适配器 | 不存在、已关闭、可用、权限／系统错误 | 给“打开 Windows 蓝牙设置”或“重试” |
| 真实手柄 | 未扫描、扫描中、已发现、连接中、初始化中、等待报文、输入正常、已断开、连接失败 | “已发现”不等于“已连接”；“GATT 已连接”不等于“按键已可用” |
| 虚拟输出 | 未选择方案、仅有安装包、驱动未安装、驱动已安装、服务启动中、设备已挂载、输入提交正常、异常、需重启 | “文件存在”不等于“驱动运行”；“设备已挂载”不等于“Steam 已识别” |
| 游戏验证 | 未检查、等待用户验证、已在目标程序验证、验证失败 | 只有集成检测或用户明确完成测试才显示“已验证”；标注测试目标和时间 |
| 配置 | 未修改、未保存、已保存待应用、应用中、已应用、应用未确认 | 文案与文件读回及运行路径分别对应 |

概览上的总状态取**最早阻断阶段**，同时保留其他阶段真实信息。例如蓝牙输入正常但虚拟输出未启动时，总状态为“等待启动虚拟手柄”，而蓝牙卡仍显示“输入正常”。断线时立即显示“实体手柄已断开”，映射预览归零；输出端只在收到中立状态并得到提交确认后显示“输入已归零”。

## 6. 关键交互流程

### 首次使用

1. 检查 Windows 11、蓝牙适配器与可用输出方案，在概览列出每项结论。
2. 用户点击“扫描手柄”，列表显示候选；选择设备后依次显示“连接蓝牙 → 检查 GATT → 初始化 → 等待输入”。可取消，失败返回可重试状态。
3. 收到持续有效的输入时显示“NS2 Pro 输入正常”；用户可以在蓝牙页预览按键和摇杆，避免先安装驱动才知道手柄是否可用。
4. 用户进入虚拟手柄页，检查选择的输出路线。驱动安装作为**显式操作**，预先显示来源、签名、版本、所需权限和预期重启要求。安装阶段显示“检查包 → 验证签名 → 请求系统权限 → 安装 → 枚举检查”。取消 UAC 后显示“安装未完成”。
5. 启动虚拟设备后检查 Windows 枚举和报文提交，再提示用户在 Steam 或目标游戏中测试。只有该测试实际完成后才记录“游戏已验证”。

### 日常启动与断线

记住上次选择的设备与映射，但不自动运行安装器。自动重连默认关闭，由用户在设置中开启。断线时停止震动、发布中立状态并显示有限次数的重连进度；恢复后仍要重新确认实时有效输入。退出应用时提示虚拟设备是否仍被服务占用，并让用户明确选择停止或继续（仅当后台服务能力已实现时出现）。

### 失败反馈

主要提示采用“发生了什么 + 下一步”的句式，如“找到手柄，但未收到有效输入。请保持配对模式并重试连接。”诊断详情包含阶段、时间、操作 ID、错误码与可复制摘要。连接超时、设备被其他程序占用、驱动签名失败、需重启、虚拟设备枚举失败、Steam 未验证应是不同错误，不合并为“连接失败”。

## 7. 控件、实时预览与性能

2026-09-26 实施补充：导航采用 `VirtualDriverControl` 同类图标与文字布局、居中对齐、蓝色选中态，并可折叠至图标宽度。测试页按实际手柄型号切换按键图，右侧固定陀螺仪状态与 3 秒静置校准，下方提供双摇杆精度、震动时长及双频力度。SDL 设备调用在专用线程执行，不在 UI 定时器中初始化 HID。当前可用范围与校准细节以 [08](08_TESTER_CALIBRATION_AND_STABILITY.md) 为准。

- 实时预览以图形按钮和数值并列显示。摇杆同时给出方向、百分比和原始／校准值入口；IMU 显示“正在接收 / 暂无数据”，不要用静止零值暗示传感器正常。
- BLE 报告处理不得依赖 UI 帧率。ViewModel 接收聚合后的最新状态，视觉刷新建议上限约 `30 Hz`；报告采样率和 UI 刷新率分别展示，避免误导延迟判断。
- 日志列表分页或虚拟化，默认不连续展示完整设备地址、原始报文或敏感环境路径。导出时提供脱敏说明与预览。
- 主操作使用异步命令，繁忙时禁用同类操作并显示当前阶段；允许取消的阶段提供“取消”，不可中断的驱动安装阶段明确说明等待原因。
- 设备名和路径可选中复制；长文本截断时提供 Tooltip 或详情。数值设置优先使用 `NumericUpDown`、`ComboBox`，带范围和单位。

## 8. 可访问性、适配与图标

- Tab 顺序与视觉顺序一致；扫描、连接、映射、驱动安装确认和日志导出均可用键盘完成。焦点状态明显；状态图标有文本或无障碍名称。
- 验证 Windows 缩放 `100% / 125% / 150% / 200%`。最小窗口宽度下状态链纵向换行、卡片改单列或双列，核心操作不需要水平滚动。
- 提示不只依赖颜色；加载状态有阶段文字。对“无蓝牙”“无手柄”“无驱动”“无网络”“用户取消权限请求”提供明确空态和可执行动作。
- 任务栏、窗口和 EXE 规划使用同一独立图标：圆角系列蓝色底，白色手柄主体配一条粗蓝牙连接弧线；不使用 Nintendo 或 Steam 标志。计划母版 `Assets/ControllerForwardingTool.svg`，ICO `Assets/ControllerForwardingTool.ico`，均**尚未生成**。在 16、32、256 像素检查轮廓与对比度。现有 `Assets/avalonia-logo.ico` 是模板资源，实施品牌图标后替换。
- 首版按参考文档实现浅色主题；暗色主题若加入，需建立对应语义令牌并逐页检查，不能只反转背景色。

## 9. 实现映射与交付检查

建议 Avalonia 分层：`Views` 只声明布局与绑定；`ViewModels` 持有展示状态、异步命令和用户动作；蓝牙、协议、驱动服务通过接口提供真实状态。`App.axaml` 放令牌、导航、卡片、按钮和状态徽标样式；不要让 ViewModel 通过颜色字符串传递业务状态。窗口关闭时取消扫描和 UI 订阅，驱动安装／设备服务生命周期按明确策略处理。

以下各项都满足后，才认为 UI 实施符合本文：

- 概览能独立显示蓝牙、实体输入、虚拟输出、游戏验证四段，且每段状态来源可追踪。
- 六个一级页面遵循相同的标题、说明、状态、操作、内容卡片顺序；可在最小窗口和 200% 缩放下完成扫描、连接、启动输出与查看错误。
- “发现设备 / GATT 已连 / 实时输入正常”“安装包存在 / 驱动已安装 / 虚拟设备已挂载 / Steam 已验证”均显示不同文字，不被一个绿色勾覆盖。
- 映射保存与应用反馈分开；额外键无映射时有明确标记；断线、权限拒绝、驱动错误和需重启各有可执行下一步。
- 首次启动不自动安装或执行随附 USB/IP 包。虚拟设备和 Steam 的状态只由实际检查或用户实测确认。
- 本文是设计验收依据，**不是已实现功能清单**。实施时根据已验证的真实能力更新页面可用性与文案。
