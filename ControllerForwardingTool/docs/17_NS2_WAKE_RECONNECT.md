# NS2 Pro 唤醒回连

更新：2026-09-26。

后续用户实测普通唤醒失败、SYNC 可用。新的广播目标诊断、25 秒服务发现重试、本地重命名，以及尚未实现的主机注册，见 [18](18_NS2_HOST_REGISTRATION_PROPOSAL.md)。下文 8 秒探测及早期验证记录保留为实现历史。

## 原因与改动

旧版断线后只重新扫描，且每条广播都需要匹配 Nintendo 厂商字段或名称。没有保存可用于回连的设备记录。长按 SYNC 进入配对广播能帮助程序再次发现设备，但已有输入连接不能据此推断完成了主机注册/绑定。

初版回连实现（多设备列表更新见下节）：

- 只有完成 GATT 检查、初始化并收到有效 FD2 输入后，才把设备地址、地址类型和显示名称存入 `bridge-settings.json` 的 `LastBleDevice`。保存失败不影响当前输入或本次运行中的设备记忆。
- 启动时恢复设备记录；按地址及类型匹配的广播即使没有名称/厂商字段也进入候选。地址不是身份认证，仍重新检查必要特征与有效输入。新地址继续走原有发现流程；有效连接会更新记录。
- 每次扫描先保留 3 秒发现窗口，再尝试已记住地址。设备打开、GATT 会话建立和服务枚举阶段最多等待 8 秒；服务响应后保留原有初始化流程，整次连接仍最多 60 秒。每次连接尝试结束后至少 15 秒再探测已记住地址；广播候选失败冷却仍为 10 秒。
- 停止自动连接会取消在途尝试；手动断开还会释放已建立会话。退出取消连接；断线清理期间禁止启动新连接。自动恢复始终重新初始化并等待有效输入，避免仅凭 Windows 连接状态判定成功。
- 每轮扫描累计广播、候选与已记住地址广播数量；主动探测前及长时间扫描时输出汇总。日志明确区分候选连接、按记录主动回连、GATT 响应、连接取消与超时。地址只显示末尾部分。

没有增加未经验证的配对命令，也没有把 L + R 当成应用层触发条件：BLE 连接建立前应用收不到手柄按键。Windows 能否收到并连接普通唤醒广播、手柄是否需要额外的主机绑定流程，仍需实机确认。

## 已连接过的手柄列表

蓝牙连接页新增持久化历史列表，显示设备名称、地址末尾和地址类型。收到有效输入后添加记录；重复连接更新记录并移到顶部。扫描可识别列表中任意设备的无名称广播，主动地址探测轮流尝试列表中的设备，防止离线的第一只手柄阻挡其他设备。

配置存入 `BleDevices.Remembered`，上一版 `LastBleDevice` 会自动迁入；保存后清空旧字段。地址和地址类型共同标识记录，加载时过滤无效项并去重。

选择设备并点击「删除选中记录」即可删除。先保存再更新界面，写入失败时保留原记录并显示原因。删除中的连接尝试会取消，已经建立的连接继续使用。删除的地址保存在 `BleDevices.Forgotten`，防止下一条广播或重启后立刻自动连接并恢复记录；它仍可出现在扫描列表。手动选中并连接成功后会清除此地址的自动连接排除记录，再次加入历史。

历史列表管理的是本工具成功接入的 NS2 BLE 手柄，不修改 Windows 系统配对。无法通过地址把使用新随机地址的设备确定为同一只手柄；地址变化时可能产生新记录。

列表版验证：使用 `artifacts/history-build` 独立目录完成 Release 构建，0 警告 / 0 错误；30 项回连/历史检查全部通过，新增覆盖多设备、去重排序、删除持久化、旧记录不复活、手动重新记住和无效记录清理。尚未完成实体多手柄和窗口交互验收。

## 验证

`ControllerForwardingTool.Checks` 是无需手柄的控制台回归检查，覆盖：无名称的已知设备、地址类型冲突、未知邻近设备、变化地址与首次发现、配置序列化/旧配置/损坏配置/迁移、扫描窗口和重试冷却。它不会访问蓝牙硬件，不能证明物理 L + R 回连成功。

```powershell
dotnet build ControllerForwardingTool.slnx -c Release
dotnet run --project ControllerForwardingTool.Checks -c Release
```

本次验证结果：独立构建目录中 Release 构建成功，0 警告 / 0 错误；21 项无硬件检查全部通过。原构建目录写入受限，Avalonia 构建统计任务访问用户目录也受限，因此验证时使用以下命令隔离输出并跳过构建统计（不修改项目默认配置）：

## 实机验收步骤

1. 使用新版本，先长按 SYNC 连接一次，确认日志显示“收到有效输入”和“已记住本次有效连接”。旧版本留下的摇杆校准地址不能替代这一步。
2. 让手柄休眠/断开，保持自动连接开启，按 L + R 唤醒。观察是否收到有效输入，检查按键与摇杆。再重启应用重复此步骤，验证持久化回连。
3. 无响应时导出日志。比较已记住设备广播数量、主动回连日志和 GATT 服务是否响应；再长按 SYNC 对照。不要仅凭零广播计数判断是手柄固件问题。
4. 回连过程中点“停止自动连接”，确认不再发起新尝试；点“扫描手柄”恢复。点“断开连接”后即使唤醒手柄也不应自动连接，重新开启自动连接后才恢复。
5. 手柄关闭或改连其他主机时，确认界面仍可操作、扫描继续、输出保持中立。使用另一只手柄或改变地址后长按 SYNC，确认仍能发现并更新设备记录。

6. 分别连接两只手柄，确认历史均保留且最近连接的在前。删除其中一只，重启后它仍不在历史中、不会自动连接，另一只仍可自动回连。扫描后手动连接已删除的手柄，确认记录恢复。
7. 分别在回连期间及已连接后删除对应记录，确认前者取消尝试且不重新添加，后者继续接收输入。删除最后一条记录后，列表为空且删除按钮禁用。

这些步骤尚未通过本次自动检查完成实机验收。
