## 当前证据

用户实测：L + R 唤醒后 GATT 返回 Unreachable，长按 SYNC 可以正常连接。当前代码只初始化输入，未完成本机蓝牙地址交换和配对确认。上一版的设备列表只记录电脑端地址，不能替代手柄端注册。

公开逆向研究描述：Pro2 厂商广播包含目标主机地址；SYNC 广播该字段为零。Nintendo 使用自定义 GATT 配对流程，其主机注册与读取输入是分开的。[广播及配对研究](https://github.com/ndeadly/switch2_controller_research/blob/master/bluetooth_interface.md#pairing)、[命令说明](https://github.com/ndeadly/switch2_controller_research/blob/master/commands.md#command-0x15---bluetooth-pairing)。这不是 Nintendo 官方规范，尚需当前固件实测。

## 已实施且不写手柄配对信息的修改

- 解析 Pro2 产品标识和广播目标；针对发往其他主机的广播显示明确提示，不再反复自动连接。扫描仍继续，可通过 SYNC 恢复普通输入连接。
- Unreachable 时保留同一会话，服务发现最多重试三次；发现阶段最多 25 秒，整次连接仍为 60 秒。权限错误不重试。此重试不能替代主机注册。
- 合并短时间内的广播与扫描响应，保留名称及连接属性，避免扫描响应抹掉可连接标志。
- 候选设备本地重命名，最多 40 字符，按地址和类型持久化；命名本身不把设备标记为连接成功。空名称恢复原名。

## 待授权的主机注册方案

触发条件：用户长按 SYNC，收到明确的 Pro2 配对广播，并完成必要 GATT 特征验证。仅对这种首次注册流程写入；普通回连不重复配对。

1. 读取实际使用的本机蓝牙适配器地址，通过配对命令交换地址，核对响应手柄地址。
2. 使用新随机密钥材料和随机挑战，校验手柄的密码学确认响应。严格匹配命令和子命令的 ACK；超时、地址不符或确认失败就停止，不提交注册。
3. 仅在校验成功后发送最终提交命令，把本机地址和配对信息保存到手柄。
4. 完成原有输入初始化，收到有效输入后显示注册结果。日志不记录密钥材料。
5. 实机验收：一次 SYNC 注册后，分别测试休眠唤醒和重启程序后的 L + R 回连；确认广播目标为本机且输入有效。

这会改变手柄持久保存的回连目标，可能影响它与原 Switch 主机或其他电脑的回连。不会清空全部配对记录、执行通用闪存写入、安装驱动或调用 Windows 标准 SMP 配对。具体固件如何保留原有主机记录仍须实测。
