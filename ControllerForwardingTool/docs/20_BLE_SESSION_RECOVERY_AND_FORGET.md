# GATT 会话恢复和逐项删除

> 历史记录（1.0.1 文档同步，2026-09-27）：正文保留当时的设计、功能状态与验证结果，不作为当前操作说明。当前键鼠 / 混合输入、全输入映射、NS2 USB 连接及默认配置见[当前文档目录](../../docs/README.md)和[1.0.1 更新日志](../../CHANGELOG.md)。

## 实际日志

2026-09-26 的用户日志显示：20:11:33 的连接在同一会话三次服务发现均返回 Unreachable；20:11:49 的新连接第一次服务发现成功，20:11:53 收到有效 FD2 输入；20:12 的后续连接又返回 Unreachable。这说明初始化并非每次都失败，截图中的错误发生在获取 GATT 服务之前。日志没有记录当时手柄的物理按键操作，不能据此断言已确定无线失败的唯一原因。

## 修改

- Unreachable 最多重试三次，每次释放失败的服务、设备对象及 MaintainConnection 会话，再重新打开地址。AccessDenied 不重试；取消和整体超时仍有效。失败后恢复扫描；手动发起连接也开启后续自动扫描。停止按钮可取消正在进行的手动连接。
- 新日志同时覆盖手动连接和自动连接的广播模式、最后发现时间、地址类型、链路/会话状态。点击扫描清除旧候选。
- 移除旧初始化序列中的 `15 91 01 03 00 01 00 00 00`。这条指令是配对提交，原序列没有先执行地址/密钥交换和挑战确认。删除该不完整操作不等于已经实现完整主机注册，也不能单凭静态分析证明它导致了这次 Unreachable。[原始研究](https://github.com/ndeadly/switch2_controller_research/blob/master/commands.md#subcommand-0x03---finalise-pairing)。
- 每一条历史记录右侧有独立删除按钮，参数就是该行设备的地址和类型。保存失败保留原记录；保存成功清除本地历史及别名，并取消该设备的在途连接、断开当前连接。其他手柄的记录和别名保留。
- 仅用户点击删除时，检查对应 Windows 设备的 Pairing 状态；如果已配对则调用 UnpairAsync。不在 GATT 重试中自动取消系统配对。如果系统取消配对失败，明确显示本地删除已完成、系统配对未能清理，不伪报全部成功。[Windows API](https://learn.microsoft.com/en-us/uwp/api/windows.devices.enumeration.deviceinformationpairing.unpairasync)。
- 保留没有名称的地址排除项，防止后台扫描或程序重启把删除的记录立即加回。再次使用需长按 SYNC，并显式点击“重新配对选中设备”；必须在最近 5 秒内收到有效的配对模式广播。仅收到扫描响应不能更新旧配对模式的时间。成功收到输入后重新记住设备，旧别名不恢复。

本功能不清空手柄固件中的其他主机，也未实现自定义的主机注册流程。L + R 是否能回连仍取决于已有主机注册状态；不能把本地记录列表当作注册成功。

## 验证

Release 编译和 67 项无硬件检查通过；实际启动界面已检查行末删除按钮和停止操作。未点击删除用户的真实设备进行测试。保持原有 LocalAppData 配置、日志及运行目录规则。

尚需实机验证：保持 SYNC 闪灯时连接并收到输入；删除已连接设备后连接断开、历史和名称消失；重启不自动接回；重新进入 SYNC 模式并点击配对后恢复输入。没有把这些待验证项记作已通过。
