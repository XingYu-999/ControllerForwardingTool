# 自动连接、通用手柄测试与虚拟 USB

> 历史记录（1.0.1 文档同步，2026-09-27）：正文保留当时的设计、功能状态与验证结果，不作为当前操作说明。当前键鼠 / 混合输入、全输入映射、NS2 USB 连接及默认配置见[当前文档目录](../../docs/README.md)和[1.0.1 更新日志](../../CHANGELOG.md)。

更新：2026-09-26。模式与配置见 [09](09_ARENA_AND_CONTROLLER_LAB.md)，r5 三轴姿态/高级校准见 [11](11_MOTION_CALIBRATION_AND_PUBLISH.md)，r6 Windows 手柄作为转换输入见 [12](12_MULTI_CONTROLLER_INPUT.md)。本文描述连接基础实现；协议研究笔记不等于硬件验收结果。

## NS2 Pro BLE

- 启动应用即主动扫描，支持 Nintendo 厂商字段及 Pro Controller / Pro2 / Switch / Nintendo 名称候选。
- 收到有效 FD2 后保存上次设备地址及地址类型；后续接受该设备无名称/厂商字段的广播。每次开始扫描先留出 3 秒发现窗口，再尝试已记住地址；无广播的地址尝试在打开设备/枚举服务阶段限时 8 秒，收到 GATT 服务响应后继续原有初始化。一次尝试结束后至少 15 秒再发起已记住地址探测，期间继续扫描新地址。
- 发现候选后串行尝试 GATT 连接，检查命令、ACK、FD2 特征。名称只能筛选，不能确认设备身份。
- 使用参考桥接工程的 15 条初始化命令。原首条命令经逐字节核对是正确的 16 字节，未追加或删减字节。
- 修正第 7 条初始化命令多出的末尾 `00`：由 29 字节恢复为参考程序的 28 字节（8 字节头 + 20 字节负载）。15 条命令已与参考源码逐字节比较；检查程序验证声明负载长度与实际长度一致。此修正的真实蓝牙效果仍需 NS2 实测。
- 维持 GATT 会话；订阅与写入最多重试 3 次。单次连接最多 60 秒，FD2 订阅后等待有效首帧最多 6 秒。ACK 原文记录在日志，未宣称校验其完整语义。
- 候选失败后间隔 10 秒再试，扫描轮次间隔至少 2 秒。设备丢失或 2 秒无有效输入时重新扫描；虚拟输出在无新输入超过 250 ms 时先归零。
- 「停止自动连接」关闭自动搜索并取消正在进行的连接；「断开连接」还会释放已建立连接。两者都暂停自动回连，已记住设备记录保留。
- 虚拟设备可以先启动，保持中立输入，再唤醒实体手柄。BLE 本身不依赖虚拟驱动。

已在此版本连接过的手柄可尝试按 L + R 唤醒。首次连接、地址改变后无法发现或回连无响应时，长按顶部 SYNC 重新广播。若一直搜索：确认系统蓝牙开启、未连接 USB，并关闭另一个正在占用实体 NS2 的桥接程序。日志记录扫描广播/候选/已记住设备广播数量，以及主动回连、GATT、写入、ACK、有效首帧阶段；扫描计数为 0 不足以证明手柄没有广播。绑定要求与实机验证边界见 [17](17_NS2_WAKE_RECONNECT.md)。

## 手柄测试

测试页通过 SDL 3 识别标准手柄与通用 HID，自动热插拔并保留选中设备。它处理 NS1 USB/蓝牙 HID 初始化；不再只依赖 Windows.Gaming.Input.Gamepad。

- 已有系统蓝牙连接的 NS1、Xbox、PlayStation 等可自动发现。应用不会替这些设备完成首次系统配对。
- 标准布局显示按键高亮、双摇杆坐标和所有轴值；未知 HID 保留原始编号，不猜测按钮含义。
- SDL 标准按钮编号采用位置定义；图形按 Switch、Xbox、DualShock、DualSense 型号显示，只列出设备报告支持的按钮。原始 HID 的轴顺序取决于设备。
- 电量、陀螺仪和加速度取决于设备是否提供。r5 起姿态融合陀螺仪和重力，包括相对航向；无磁力计不能提供绝对航向，详见 11。
- 右侧陀螺仪面板提供原始/校准后角速度及 3 秒静置校准。采样、门限与作用范围见 [08](08_TESTER_CALIBRATION_AND_STABILITY.md)。
- 震动测试可设置 50–10000 ms、低频与高频各 0–100%，可手动停止，不支持时显示错误。r3 将 PS5/Edge/Xbox/NS2 主机震动转码回实体 NS2 BLE；NS1 回传仍未实现，物理震感待实测。
- NS2 USB 需要随附的定制 SDL 3.4.16 与 libusb 1.0.30。该初始化接口独占；测试前关闭其他测试工具，开始游戏前切换到概览，程序会释放测试接口。
- 「NS1 输出映射预览」显示映射前后的本地状态。验证 Windows 真正接收了数据，必须选择「Windows 手柄」。

## 虚拟输出

r6 起虚拟页可选择 NS2 Pro 直连蓝牙或 Windows 实体手柄作为输入。Windows 模式支持 Xbox、NS1、PS 等 SDL 标准映射设备；先选实体输入再启动输出。下表是输出身份所能承载的能力，源没有对应能力时该功能保持无输入，不会生成假的传感器或背键信号。

| 模式 | 实现 | 输入能力 |
| --- | --- | --- |
| NS2 Pro，057E:2069 | 随附 VIIPER 独立进程 + 本机 USB/IP | 按键、12 位摇杆、原始 IMU，保留 C/GL/GR |
| PS5，054C:0CE6 | VIIPER dualsensehaptic | 按键、摇杆、体感、普通/HD 震动 |
| Xbox，045E:028E | VIIPER xbox360 | 按键、摇杆、双马达 |
| PS5 Edge，054C:0DF2 | VIIPER dualsenseedge | 按键、背键、摇杆、体感、普通震动 |
| NS1 Pro，057E:2009 | C# USB/IP 设备 + HID 协议应答 | 同名按钮、12 位摇杆；C/GL/GR 忽略，IMU 保持中立 |

启动只绑定回环地址，使用空闲端口，通过安装好的 usbip.exe 挂载，并保存本次获得的端口。停止和退出只卸载自己创建的设备及后端，不对其他程序执行全局 detach。

NS1 实现包括 0x80/0x81 USB 握手、0x21 子命令应答、设备信息、0x30 输入模式、玩家灯状态、SPI 工厂校准与颜色读取。其他输入模式返回不支持。SPI 长度上限 29，越界请求拒绝。校准是与虚拟输入对应的合成数据，不冒充实体 NS2 工厂校准。

输入通道保存一个最新状态，由独立高精度计时器发送，不积压旧动作。断线和超时会提交中立状态。窗口关闭会等待连接取消和设备清理完成。

NS1 USB/IP 应答运行在线程池，SDL 设备初始化和采样在专用线程，避免初始化等待 USB 应答时阻塞 UI。`--attach-monitor` 可重复验证这一输入架构。

## 驱动入口

「虚拟手柄」分别显示随附安装器与系统驱动注册/客户端状态。注册不等于运行、挂载不等于游戏识别。

安装前检查固定 SHA-256 和签名者，再打开随附 USBip 0.9.7.7 x64 安装向导。卸载先停止本应用虚拟设备，再打开已安装 USBip 的官方卸载器；系统驱动可能被其他软件使用。UAC 由用户操作，取消和错误码会显示在页面。没有自动静默安装，也不会更改签名策略。

## 验收

`NS2ProWin11.Checks` 默认仅检查协议与回环服务，不挂载设备。`--devices` 列出 SDL 实际识别的设备。`--attach` 显式使用现有驱动创建临时虚拟 NS2/NS1，注入按键/摇杆、从 SDL 读回并验证归零，finally 清理；`--attach --ns1` 只验证 NS1。

仍需用户实机检查：NS2 首次发现、配对广播和断电回连；不同固件与蓝牙适配器；真实摇杆方向/范围与 IMU 标定；Steam/Eden/游戏中的使用。合成输入集成测试不能代替实体无线链路验收。
